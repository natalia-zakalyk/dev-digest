## Goal and non-goals

**Goal.** For a PR, show (1) the symbols declared in its changed files, (2) who calls them (`file:line`, linked to GitHub at the head sha), (3) the HTTP endpoints and crons that may depend on them. Two consumers of one server route `GET /pulls/:id/blast`:
- A. a "Blast radius" card on the PR Overview tab (next to the Intent card);
- B. the real `get_blast_radius` MCP tool in `mcp/` (replaces the stub), returning the same map.

The feature **reads** the prebuilt repo-intel index through the existing facade (`repoIntel.getBlastRadius`, `repoIntel.getIndexState`), maps it to a contract, and shows it. No LLM, no new parsing, no new outbound host, no DB schema change.

**Non-goals.**
- No change to how the index is built (`server/src/modules/repo-intel/pipeline/*`), no new table, no migration.
- No BFS / transitive callers beyond what the facade returns.
- No writes from MCP (no resync from the tool; only a hint).
- P3 items are listed as OPTIONAL steps (O1–O6) and are not part of the core plan.

## Decisions (to confirm in S0)

| # | Question | Proposed decision |
|---|---|---|
| D1 | Contract | New `BlastRadiusResponse = BlastRadius.extend({ counts, degraded, reason })` in `contracts/review-api.ts` of **both** copies, next to `SmartDiffResponse` (`server/src/vendor/shared/contracts/review-api.ts:83-85`). `BlastRadius` and `PrBrief` stay unchanged. `counts = {symbols, callers, endpoints, crons}` so UI and MCP show the same numbers without re-deriving them. `reason` = `z.enum(['flag_off','index_failed','index_partial','repo_too_large','no_data']).nullish()`. |
| D2 | Degraded state and "no re-parsing" | Service order: flag off → `{degraded:true, reason:'flag_off'}`, no facade call. Else `getIndexState(repoId)`: `full` → call `getBlastRadius` once, `degraded:false`; `partial` → call once, `degraded:true, reason:'index_partial'` (data still shown); `degraded`/`failed`/no row → no blast call, `degraded:true`, `reason = state.degradedReason ?? (status==='failed' ? 'index_failed' : 'no_data')`. If the facade still returns `degraded:true` (race), pass `reason ?? 'no_data'`. The ripgrep fallback is therefore never reached in the normal flow. |
| D3 | Shape of `downstream` | One entry per **unique changed symbol name that has ≥1 caller** after filtering, sorted by best caller rank desc, then name. Symbols without callers stay only in `changed_symbols`; the UI shows how many have none. |
| D4 | Caller link | `githubBlobUrl(repoFullName, headSha, file, line)` (assignment). Lines come from the index built at the default branch; for caller files not touched by the PR they match head (risk R4). |
| D5 | Logging (P2) | The service logs one info line per request through a narrow log port passed by the route (`req.log`): `{ prId, repoId, source: 'repo_index', index_status, symbols, callers, endpoints, crons }`, message `blast: read prebuilt index`, or `blast: index unusable, skipped` with the reason. No payloads, no file contents. |
